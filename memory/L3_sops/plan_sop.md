# Plan Mode SOP (复杂任务分解)

> 简单任务（1–2 步可完成）无需本 SOP，直接做。  
> 适用于：多疾病联合评估、多数据源整合、需先查文献再定流程的诊断。

---

## 0. 基本协议

进入 plan mode 后，**立即**调用 `update_working_checkpoint`，内容包含：

1. **PLAN**：初始为 `[ ] 规划` `[ ] 执行`；规划完成后展开为详细 checklist。
2. **RULES**（以下三条原文保留，每次 update 必须带齐）：
   - 一次只做一步，完成后标 `[x]` 并 update checkpoint。
   - 每次 checkpoint 必须保留完整 PLAN + RULES。
   - 全部 `[x]` 才可收尾。

---

## 1. 规划阶段

初始 checkpoint：`[ ] 规划` `[ ] 执行`。「规划」完成 = 已展开执行步骤并 update checkpoint。

### 1a. 读 SOP

- 查 L1 索引找相关疾病 → 读对应 L3 SOP。SOP 提供任务骨架（诊断标准、推荐基因/蛋白、风险分层）。
- 不确定性最高的环节先探（例如：某病无 L3 SOP → 先 `web_search` / `browse_and_learn` 再定步骤）。

### 1b. 分类

从依赖关系读出结构：

- **有依赖** → Sequential：`[ ] 临床/影像 → [ ] 基因/蛋白 → [ ] 整合报告`
- **无依赖**（多指标并行）→ MapReduce：`MAP: [ ] 基因 [ ] 蛋白 … REDUCE: [ ] 汇总`
- **条件未知** → Branch：`[ ] 尝试 X → 成功:[ ] Y / 失败:[ ] Z`

### 1c. 分解

按结构展开 checklist，每步须有**独立完成判据**，否则继续拆。然后 update checkpoint 并标 `[x] 规划`。

- **Seq**：`[ ] A → [ ] B → [ ] C`
- **MR**：`MAP: [ ] D1 [ ] D2 … REDUCE: [ ] 汇总`
- **Branch**：`[ ] 尝试 X → 成功:[ ] Y / 失败:[ ] Z`

---

## 2. 执行注意

- 计划有误时回到规划修正，不硬凑；**不可逆操作**（如写入 L2/L3）前多验证一步。
- MapReduce 的 MAP 若未来支持 subagent，可并行执行；当前为单线程则顺序执行 MAP 步骤。
- 步骤间尽量用**文件/工具结果**传递中间结果和汇总，不靠上下文记忆。
- 收尾：全部 `[x]` 后汇总结果，清理 checkpoint。

---

## 3. 诊断场景示例

- **单病多源**：`[ ] 读 L3 疾病 SOP` → `[ ] 查基因工具` → `[ ] 查蛋白/临床` → `[ ] 写诊断结论`
- **多病筛查**：`MAP: [ ] 病A [ ] 病B [ ] 病C` → `REDUCE: [ ] 综合风险与建议`
- **缺知识**：`[ ] 搜索/深读指南` → 成功: `[ ] 更新 L3 并继续` / 失败: `[ ] 基于现有证据给出置信度与局限`
