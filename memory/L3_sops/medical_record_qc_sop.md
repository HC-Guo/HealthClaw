# 病历智能质控与结构化补全 SOP

## 触发条件
- 用户粘贴/上传一份病历文本（门诊/住院/出院小结）
- 用户说「帮我检查这份病历」「病历质控」「检查病历完整性」

## 流程

### Step 1: 结构化抽取
```
extract_medical_record(raw_text=病历文本, record_type="住院/门诊/出院")
```
抽取为标准结构：
- 主诉 (chief_complaint)
- 现病史 (hpi) — 含发病时间线
- 既往史 (past_history)
- 个人史 (personal_history)
- 家族史 (family_history)
- 查体 (physical_exam)
- 辅助检查 (auxiliary_exam)
- 诊断 (diagnoses) — 主诊断 + 其他诊断
- 治疗方案 (treatment_plan)
- 用药 (medications)

### Step 2: 质控检查
```
check_medical_record(structured_record=Step1输出)
```
按严重程度分级检查：

**🔴 错误级（必须修正）**
- 主诉与诊断明显矛盾（如主诉「腹痛3天」诊断「脑梗死」无解释链）
- 时间线不合逻辑（入院后检查出现在入院前）
- 过敏药物出现在用药方案中
- 诊断缺少必要支持证据（如诊断「糖尿病」无血糖/HbA1c记录）
- 手术/操作与诊断不匹配

**🟡 警告级（建议补充）**
- 缺少关键阴性鉴别（如胸痛未记录心电图）
- 家族史/过敏史标注为「未询问」或缺失
- 查体缺少与主诉相关部位（如腹痛无腹部查体）
- 用药缺少剂量/频次/疗程
- 诊断顺序不当（次要诊断排在主诊断前）

**🟢 建议级（可选完善）**
- 现病史缺少「诱因→症状→演变→诊疗经过」叙事结构
- 可补充的鉴别诊断
- 辅助检查结果未在诊断分析中引用

输出: {issues: [{level, field, description, suggestion}], score: 0-100}

### Step 3: 生成质控报告与补全建议
格式:
```
质控得分: 78/100
🔴 错误 2 项 | 🟡 警告 3 项 | 🟢 建议 1 项
───────────────────────────
🔴 [诊断依据不足] 诊断「2型糖尿病」但病历中未见血糖或HbA1c记录
   建议: 补充「空腹血糖 XX mmol/L, HbA1c XX% (YYYY-MM-DD)」

🟡 [查体不完整] 主诉「腹痛」但腹部查体缺失
   建议: 补充「腹部: 腹软/压痛/反跳痛/肠鸣音」描述
...
```

对缺失字段提供模板化补全草稿（Agent 根据上下文推断合理内容）

### Step 4: 用户确认
```
ask_user → 逐项展示，用户选择: 接受/修改/拒绝
```

### Step 5: 回写与联动
- 将确认后的结构化病历保存到 user_data/
- 如病历中包含用户健康信息（慢病/过敏/用药）→ update_user_profile 自动联动
- 如发现用药信息 → 可触发 medication_review_sop 进行用药审查

## 质控规则来源
- 内置规则: 主诉-诊断一致性、时间逻辑、必要字段完整性
- L3 SOP 引用: 对应疾病的 SOP 提供该病必查项（如 breast_cancer_sop 要求家族史）
- 不确定时: web_search 查阅临床病历书写规范

## 注意事项
- 质控是辅助，不是定性。用「建议补充」而非「错误」措辞面向用户
- 涉及诊断判断: 标注「仅为质控提示，以临床医生判断为准」
- 隐私: 病历内容不通过网络传输，质控全程本地完成
