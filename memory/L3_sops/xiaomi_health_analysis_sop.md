# 小米运动健康分析 SOP

## 适用场景
- 需要通过 Android 手机读取“小米运动健康 / 小米健康”App中的健康数据。
- 当前已验证场景：**压力（Stress）周视图数据读取与分析**。
- 适用于首页入口不稳定、图表较多、文本信息不完整的界面。

## 证据与适用边界
- 证据来源：基于已成功完成的真实工具调用流程（`phone_control` + `phone_screen_analyze`）。
- 当前仅对以下经验做行动验证：
  - 可用包名：`com.mi.health`
  - 首页未必直接显示“压力”入口，常需先下滑到健康卡片区
  - 进入压力详情后需要切换到“周”视图再读取
  - 读取时优先 `ui_dump`，不足时再用视觉分析
- 未验证内容不要视为固定规则，例如：
  - 不同版本 App 的页面布局
  - 月/年视图字段完整性
  - 睡眠、心率、步数等其它模块的稳定读取路径

## 前置条件
1. Android 手机已通过 ADB 正常连接。
2. `phone_control(action="check_connection")` 可成功返回。
3. 手机中已安装小米健康相关 App。
4. 默认优先尝试直接启动包名，而不是依赖桌面图标识别。

## 推荐启动方式
### 首选包名
- `com.mi.health`

### 推荐动作
- 直接启动：
  - `phone_control(action="launch_app", app="com.mi.health")`

### 说明
- 已验证 `com.mi.health` 可直接启动到小米健康/小米运动健康主界面。
- 若未来包名失效，再用 `list_apps` 或桌面视觉识别回退排查。

## 标准流程：读取“压力”周数据
### Step 1. 启动 App
- 使用包名 `com.mi.health` 启动。
- 启动后先确认当前页面是否为小米健康首页。

### Step 2. 定位“压力”入口
优先使用：
- `phone_control(action="ui_dump", keyword="压力")`

如果首屏未找到“压力”：
- 执行下滑：
  - `phone_control(action="scroll_down")`
- 再次 `ui_dump` 检查“压力”相关元素。

### Step 3. 进入压力详情页
- 找到“压力”卡片后点击进入。
- 若 `ui_dump` 可定位到可点击元素，则优先基于坐标/元素点击。
- 进入后先确认页面中是否存在“日 / 周 / 月 / 年”等时间粒度切换。

### Step 4. 判定并必要时切换到“周”视图
- 进入压力详情后，不要机械地先点一次**“周”**。
- 先用 `ui_dump` 判断当前是否已经处于周视图；若页面顶部已显示一周日期区间，且界面存在“日 / 周 / 月”切换并呈现周汇总结构，可先按周视图直接读取。
- 只有在确认当前仍停留在“日”视图时，再切换到**“周”**。
- 若默认停留在“日”视图，不要直接分析单日数据并误报为周结果。
- 每次点击或切换后，需等待 1-2 秒并重新 `ui_dump` / 截图确认页面状态，再继续读取。

### Step 5. 读取周统计
优先顺序：
1. `phone_control(action="ui_dump")`
2. 若文本不完整、统计值在图表区域、或日期/柱状图难以从 UI 提取，再使用：
   - `phone_screen_analyze(question="请读取当前小米健康压力周视图中的平均压力、压力等级、最大值、最小值，以及哪些日期没有数据")`

## 周视图重点读取字段
至少提取以下信息：
- 统计周期（如本周日期范围）
- 平均压力
- 压力等级（如轻度压力）
- 最大值
- 最小值
- 无数据日期

## 推荐输出格式
可按如下结构整理：
- 周期：YYYY/M/D – YYYY/M/D
- 平均压力：XX
- 压力等级：XX
- 最大值：XX
- 最小值：XX
- 无数据日期：X月X日、X月X日

## 读取策略
### 策略 1：先结构化，后视觉
优先用 `ui_dump` 的原因：
- 成本更低
- 文字更稳定
- 便于后续复核与自动抽取
- 可优先使用 `phone_control(action="tap_keyword_confirm", keyword="压力", confirm_keyword="周")` 这类原子动作，减少「找元素+点击+确认」的多轮调用

### 策略 2：图表场景切视觉分析
以下情况应切到 `phone_screen_analyze`：
- `ui_dump` 只能看到部分标签，看不到核心数值
- 数据主要以图表、柱状图、趋势图形式展示
- 无法确认哪些日期缺失数据
- 页面元素文本过少，但视觉上明显存在统计信息

### 策略 3：以“周”汇总为主，不混入单日描述
- 若用户要求周分析，应确保当前真的在“周”标签。
- 不要把单日卡片数值当作整周平均值。

## 验证点
完成读取前至少检查以下几点：
1. 当前 App 确认为小米健康相关页面。
2. 当前模块确认为“压力”详情，而非首页卡片预览。
3. 当前时间粒度确认为“周”。
4. 已拿到至少 4 类核心字段中的大部分：
   - 平均值
   - 等级
   - 极值
   - 无数据日期
5. 若字段缺失，应明确说明“未读取到”，不要脑补。

## 常见坑
### 坑 1：首页首屏没有“压力”
- 现象：启动后看不到压力入口。
- 原因：压力卡片可能在更下方的健康卡片区。
- 处理：先下滑，再检索“压力”。

### 坑 2：进入了压力页，但不要想当然机械点“周”
- 现象：页面已显示一周日期区间或周汇总结构，但仍误以为必须先再点一次“周”；或者页面其实仍是某一天的详情。
- 处理：先判定当前是否已在周视图；只有确认仍停留在“日”视图时，再切到“周”读取本周统计。

### 坑 3：`ui_dump` 看不到图表中的关键统计
- 现象：能看到少量标签，无法完整读取平均值或无数据日期。
- 处理：改用 `phone_screen_analyze` 做视觉补充。

### 坑 4：把卡片预览值误当完整结论
- 现象：首页“压力”卡片显示一个数值和等级，但这通常不是完整周分析。
- 处理：必须点进详情页再读。

## 回退策略
按以下顺序回退：
1. `phone_control(action="tap_keyword_confirm", keyword="压力")`
2. 若未命中，`scroll_down` 后再次 `tap_keyword_confirm(keyword="压力")`
3. 进入详情后，必要时 `tap_keyword_confirm(keyword="周", confirm_keyword="周")`
4. 全量 `ui_dump`
5. 若仍不完整，使用 `phone_screen_analyze`

若仍失败，再考虑：
- 查看当前前台应用是否正确：
  - `phone_control(action="current_app")`
- 重新启动 App：
  - `phone_control(action="launch_app", app="com.mi.health")`

## 安全边界
- 仅做数据读取与分析，不进行医疗诊断。
- 不根据单周压力数据给出确定性医学判断。
- 若未来读取到极端异常或用户伴随明显不适，应提示结合线下专业意见处理。
- 不将未实际读取到的数据补全为“推测值”。
