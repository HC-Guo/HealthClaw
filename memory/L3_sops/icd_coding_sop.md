# 病案首页编目与编码辅助 SOP

## 触发条件
- 用户提供病历/出院记录要求编码
- 用户说「帮我编ICD码」「病案首页」「编目」「给诊断编码」

## 流程

### Step 1: 病历信息抽取
```
extract_medical_record(raw_text=病历文本)
```
重点提取:
- 主要诊断 (Main Diagnosis)
- 其他诊断 (Other Diagnoses，按临床重要性排序)
- 手术/操作 (Procedures)
- 病理诊断（如有）
- 损伤/中毒外因（如有）

### Step 2: ICD 编码建议
```
suggest_icd_codes(diagnoses=[...], procedures=[...], icd_version="ICD-10")
```
对每个诊断/操作:
1. 给出候选 ICD-10 编码（前 3 个最可能）
2. 标注置信度（高/中/低）
3. 低置信度时自动 web_search 确认

输出格式:
```
主要诊断: 2型糖尿病伴周围神经病变
  → E11.4  2型糖尿病伴神经系统并发症 [置信度: 高]
  → E11.40 ... [置信度: 中]
  证据: "HbA1c 9.2%, 肌电图示周围神经传导速度减慢"

其他诊断1: 原发性高血压
  → I10 原发性(特发性)高血压 [置信度: 高]
```

### Step 3: 证据引用
对每个编码建议，标注病历中的支持证据:
- 引用原文位置（如「现病史第3段」「辅助检查: HbA1c 9.2%」）
- 编码选择依据（如「选E11.4而非E11.5，因以神经病变为主要表现」）
- 证据不足时标注 ⚠️

### Step 4: 编码规则核验
```
validate_icd_combination(codes=[...])
```
检查:
- **主诊断选择原则**: 消耗资源最多 / 对健康危害最大 / 本次住院主要治疗目标
- **合并编码 vs 独立编码**: 糖尿病+并发症应用合并编码 (E11.x)
- **排除码/包含码**: 检查是否有互斥编码
- **手术与诊断一致性**: 手术操作应对应相关诊断
- **编码特异性**: 是否可以编到更具体的亚目（如 I10 vs I10.x01）

发现问题则标注并给出修正建议

### Step 5: 复核确认
```
ask_user → 展示完整编码方案，逐项确认/修改/删除
```

展示格式:
```
═══════════════════════════════════
  病案首页编码建议
═══════════════════════════════════
  主要诊断: 2型糖尿病伴周围神经病变 → E11.4 ✅高
    证据: HbA1c 9.2%, 肌电图异常
  其他诊断1: 原发性高血压 → I10 ✅高
  其他诊断2: 高脂血症 → E78.5 ⚠️中
    ⚠️ 病历中缺少血脂检查记录，建议补充
  手术操作: 肌电图检查 → ...
───────────────────────────────────
  编码规则检查: ✅ 通过
═══════════════════════════════════
```

### Step 6: 输出
将确认后的编码方案保存为结构化 JSON，可用于:
- 导出 CSV 格式
- 人工复核存档
- 后续对接 HIS 系统（Phase 5 扩展）

## 编码知识策略
- **常见编码** (高频 500 个): LLM 内置知识通常准确
- **罕见编码**: web_search "ICD-10 [诊断名] 编码" 确认
- **争议编码**: 标注「建议人工复核」，给出多个候选及理由
- **版本差异**: 确认用户使用的是 ICD-10 / ICD-10-CM / ICD-11
- **经验积累**: 每次用户修正编码后记录到 L4，沉淀编码经验

## 注意事项
- ICD 编码仅为辅助建议，最终以编码员/医师审定为准
- 中文诊断到 ICD 码存在多对多关系，优先推荐最具体的匹配
- 不同医院可能有本地化编码习惯，需以用户反馈为准
